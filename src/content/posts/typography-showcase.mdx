这篇文章是一份**语法演示**，顺手当排版样例。把常用的 Markdown 语法都过一遍，看看在这个博客上的实际效果。窗口够宽的话，右侧的目录会随章节浮动高亮——这也是这次排版调过的部分。

## 行内样式

一篇好读的文章，靠的是*节奏*和**层次**。行内样式是粒度最细的那种：单词级的强调。比如这段里出现了 `inline code`、**加粗**、*斜体*，以及它们的各种组合。

可以把它们叠在一起用：***粗斜体***、**`加粗的代码`**、*`斜体的代码`*。删除线用波浪号包裹，渲染出来是 ~~这样划掉~~。链接则是 [Astro 官网](https://astro.build) 这种形式。

> 行内样式的目的不是装饰，而是给读者的眼睛一个**停靠点**。

## 标题层级

正文之上是标题。二级标题切大段，三级标题做细分。

### 三级标题：更小的切分

三级标题在目录里会缩进显示。再往下还有四级，但本站目录只收 h2 和 h3。

### 另一个三级标题

用来验证目录高亮在滚动时是否正确跳转。

2. 再做那个

## 代码块

代码块带语法高亮，亮暗主题随站点切换。

```ts
interface Post {
  title: string;
  date: Date;
  tags: string[];
}

function formatPost(post: Post): string {
  return `${post.title} · ${post.date.toISOString().slice(0, 10)}`;
}
```

Shell 也不在话下：

```bash
git init
git add .
git commit -m 'first post'
```

纯文本块没有高亮，但等宽字体依然清晰：

```
这是没有语言标注的代码块
保留所有  空格与换行
```

行内代码 `像这样` 在段落里和加粗、斜体一起出现时，应当各自有独立的视觉身份。

## 表格

| 语法 | 写法 | 效果 |
| --- | --- | --- |
| 加粗 | `**文字**` | **文字** |
| 斜体 | `*文字*` | *文字* |
| 代码 | 反引号包裹 | `文字` |
| 删除线 | `~~文字~~` | ~~文字~~ |
