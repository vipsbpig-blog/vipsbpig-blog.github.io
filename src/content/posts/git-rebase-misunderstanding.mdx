---

前几天整理分支，把一个 feature 分支 rebase 到 main 上，squash 完发现原来三个提交变成一个了。当时心里一沉——以为另外两个提交的改动丢了。

## 事情的经过

分支长这样：

```
* d3f1a2c 修复样式
* b2e4c90 加了边界判断
* a1f0c80 初版实现
```

我想把它们合成一个干净的提交，于是：

```bash
git rebase -i main
```

在编辑器里把后两行改成 `squash`，保存。然后 `git log` 只剩一个提交。我慌了。

## 其实没丢

Git 几乎不会真的丢东西。`rebase` 之后，原来的提交还在，只是没有分支指向它们了。它们活在 reflog 里：

```bash
git reflog
# d3f1a2c HEAD@{0}: rebase (finish)
# ...
```

如果你要找回原来的提交，直接：

```bash
git reset --hard HEAD@{1}
```

或者更安全的方式，先开一个分支指向那个位置：

```bash
git branch backup d3f1a2c
```

## 学到的事

> reflog 是 Git 的后悔药。只要提交过，几乎都能救回来。

`git fsck --lost-found` 还能找到即使 reflog 也过期了的悬空提交。所以 Git 的底线比想象中高——真正危险的是 `git gc --prune=now` 之后的提交。

rebase 不可怕，怕的是不懂 Git 把东西藏哪儿了。
